## 错误信息审计 + 删除闭环
### 错误信息评估（4 个问题）
- ✅ 优点：全中文前缀、有上下文（哪个槽位/哪个键）、50MB 上限有具体数字
- ❌ 问题①：原始错误是英文直接拼进去，用户看到「解析压缩包失败：invalid Zip archive: Could not find central directory end」
- ❌ 问题②：无「怎么办」——最常踩的两个坑（包里没光标文件、文件名认不出）恰恰最需要指导
- ❌ 问题③（真隐患）：`read_user_themes` 用 `.ok()?` 静默吞错，theme.json 一坏主题就凭空消失，用户只会觉得「我的主题丢了」
- ❌ 问题④：`get_all_themes` 只要 `read_system_schemes` 失败就整体失败，用户主题本可正常显示
- 已修①②③：超限报实际 MB 数、压缩包无效/找不到文件改成人话、两个槽位错误补了「怎么办」、read_user_themes 加 eprintln 可诊断
- ④ 未修（要改 command 返回结构，属新增能力非文案优化）

### 删除 + 确认弹窗
- Rust `delete_theme(theme_id)`：**必须 `Uuid::parse_str` 校验**，否则传 `../` 会让 `theme_dir` 拼到数据目录之外误删用户文件
- 三层防护：UI 按钮 disabled（内置/使用中）→ store 再校验一次 → 后端路径校验
- 不能删「正在使用」的主题：注册表还指向该文件，删了光标会异常。提示「请先切换到其它主题」
- 前端新增 `components/ui/alert-dialog.tsx`（Base UI，零依赖）、service `deleteTheme`、store `deleteTheme`（清 themes + 清 selectedThemeId）
- mock 补了第二个「已导入」主题 Neon Night，否则删除按钮永远禁用没法验证
- 验证：弹窗文案正确、2 项→1 项、选中态清空、toast 出现；截图 `docs/screenshots/{confirm-delete,deleted}.png`

### 环境坑：vite dev 崩溃
- 新增 `@base-ui/react/alert-dialog` 触发依赖重新优化，vite 要删 `node_modules/.vite/deps_temp_*`（74 个文件），被环境的 safe-delete shim 拦截（阈值 50）→ 进程直接退出，页面变成 Edge「无法连接」

## get_all_themes 部分成功契约（原留作待办的结构性问题，已修）
- 问题：`Result<Vec<CursorTheme>, String>` 单通道 + `read_system_schemes()?`，注册表一失败整锅端掉，磁盘上好好的用户主题连读都没读
- 修法：新增 `models::ThemesResult{themes, warnings}`，两个数据源独立容错——失败项进 `warnings`，只有聚合本身失败才走 `Err`
- `read_user_themes` 改返回 `(Vec<CursorTheme>, Vec<String>)`：单项损坏跳过并记 warning，目录读不了也上报（不再静默空表）
- 聚合抽成纯函数 `merge_sources`（commands/theme.rs），带 2 条回归测试「注册表失败时用户主题仍应返回」「各来源的警告应独立累积」，18/18 绿；`npx tsc --noEmit` 干净
- 前端：types 镜像 `ThemesResult`；toast 补 `warning` 档（toaster META 用 TriangleAlert + bg-warning）；loadThemes 降级时一条 toast.warning 汇总，多条时注明详见控制台
- 可迁移教训：`Result<T, E>` 里 `T` 的形状决定系统能否表达「部分成功」；聚合多独立数据源时单一 `Vec` 返回值 = 任一源炸全炸，容错必须显式设计
