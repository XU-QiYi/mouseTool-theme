## 修复：vite 缓存崩溃 + SIGPIPE 杀进程（同一根因：环境对 vite 生命周期的干预）
- **根因 1**：safe-delete shim 对项目内**单次批量删除 >50 文件** fail-closed（`tryRm`→`tryTrash`→bulk guard 递归计数）。vite 重优化会整目录 rm 旧 deps（70+ 文件）→ 进程炸掉。判别实验确认 shim 的 `shouldBypassSafeDelete` 对 **OS 临时目录**直接走原生删除（不上报、不进回收站）——这是护栏自己的豁免通道（npm 缓存暂存同等待遇）
- **修法 1**：`vite.config.ts` 设 `cacheDir` → `%TEMP%\mousetool-theme-vite-cache`。实测：种 70 个假 deps 文件 + `--force` 重优化 + `| head` 叠加，进程存活 HTTP 200，70 个旧文件全部被批量删除
- **根因 2**：后台 `npm run dev | head` 启动时管道一关，vite 写 stdout 拿 EPIPE 直接死掉。实测 node 进程在管道关闭后第 3 次写就退出
- **修法 2**：新增 `scripts/dev_bg.mjs`（stdio 接日志文件 + detached + start/stop/status，PID 落 `.dev-server.pid`），package.json 加 `dev:bg`/`dev:stop`；`vite.config.ts` 兼装 EPIPE 守护兜底（stdout/stderr error 吞掉）。实测 `| head -2` 启动 vite 后仍存活服务
- 工程教训：修「环境护栏 vs 工具」冲突时先找护栏**自己的豁免语义**（可再生缓存放临时目录），别给护栏开口子

## 重命名（rename_theme）
- 后端 `rename_theme(theme_id, new_name)`：**只改 theme.json 的 name，目录名保持 UUID**——改目录会让正在使用的光标路径失效
- `updated_at` 刻意不动：界面上它承担的是「导入于」，改名不是内容变更
- 校验顺序：UUID（防穿越）→ 空名 → 超 40 字 → 控制字符 → 文件存在 → 读 JSON → 写回；全部在碰文件系统前完成纯校验
- 前端 service 传整个 theme 对象而非 id：非 Tauri 环境可直接返回 `{...theme, name}`，让浏览器里也能走通完整交互
- 详情页标题旁 `Pencil` 按钮（`icon-xs` + `aria-label`）→ 原地变 Input，autoFocus + onFocus 全选；Enter 保存 / Esc 取消 / 失焦保存；**值没变不发请求**
- **踩坑：用 ref 存草稿**。Esc 与 onBlur 可能落在同一批 React 更新里，读 state 会拿到旧值把取消变成保存
- 内置主题不显示铅笔（系统方案名由注册表决定）；改名后若是 active，toast 注明「系统设置里的方案名会在下次应用时更新」
- 新增 3 条 Rust 测试（21/21 绿）：非法 id 拒绝穿越（delete/rename 双验）、名称校验三连、改名落盘且不动 updated_at
- 顺手消掉 paths.rs 测试函数名的 `non_snake_case` 警告，lib/bin 现在 0 warning
- 验证：`极光之夜` 改名成功，左侧卡片 + 右侧标题 + toast 三处同步；截图 `docs/screenshots/renamed.png`

## 「正在使用」状态丢失 + 卡片顶部环被裁（2026-10-21 晚）
- 症状：重开/重编译后，已应用的主题没有「使用中」标记，「应用此主题」还能点；左侧第一张卡的选中环上边被切掉
- **根因 1（状态）**：`activeThemeId` 初始就是 null，`ThemesResult` 里压根没有「当前生效」这一项——界面从没问过注册表，重开即失忆
- 修法：`get_all_themes` 增加 `active_theme_id`；后端 `registry::read_current_slots()` 读当前非空槽位（环境变量展开），`detect_active_theme` 与各主题做**双向**槽位比对（子集/超集都不算命中），路径比较统一小写 + 正斜杠归一；多主题同文件时按 `SchemeName` 择一
- 顺带：`loadThemes` 每次重新加载都清空 `selectedThemeId`（选中是临时 UI 状态），重编译后不再残留高亮
- **根因 2（布局）**：列表滚动容器 `padding-top=0`，卡片紧贴上沿；`ring` 是盒外 box-shadow，被 `overflow-y-auto` 裁掉 → 看起来像「没有上边框」
- 修法：列表容器补 `pt-2`（搜索区 pb 同步 8px，总间距 16px 仍落 2px 网格）；实测卡片上沿余量 8px
- 验证：Rust 27 测试全绿（新增 6 条：大小写/斜杠、子集、超集、路径不同、空注册表、同名择一）；本机实测 `active_theme_id = Some("sys_firefly")`，与注册表 12 个槽位一致；用伪造 IPC 的探针验「模拟重启后」→ 无高亮 + `aria-current` + 徽标 + 按钮 disabled
- `design_check.mjs` 新增硬断言：卡片顶部余量 < 2px 时 `process.exitCode = 1`
