## Toast 倒计时进度条（用户需求：悬浮期间显示剩余时间）

**做**：Toast 卡片底边内侧贴一条 `scaleX 1→0` 的 2px 细条（`h-0.5`），状态色（与左侧标识条同色同族），
圆角靠父级 `overflow-hidden` 白嫖裁切，是卡片子节点 → 进出场/FLIP 让位全跟着走，不动布局。

**改动**：
- `src/App.css`：`@keyframes toast-countdown` + `@utility toast-countdown`（origin-left、linear、forwards）；
  挂起规则 `[data-expanded]` / `html[data-toast-window-blurred]` / `html:not([data-toast-force-run])`；
  reduced-motion 下 `display: none`（条的意义就是"看着它缩短"）
- `src/components/ui/toaster.tsx`：条本体（时长 = `item.timeout`，内联 `animation-duration`）；
  `useCountdownPauseMirror` 镜像 base-ui 不写 DOM 的两个挂起信号
- `src/lib/toast.ts`：`show()` 落地新 toast 时收回豁免（addToast 会整体 pauseTimers）
- `scripts/motion_check.mjs`：+5 断言（28→33）
- 文档：`motion.md` §2 例外 + §3 Toast 行 + §5 无障碍 + §7 计数 + §8 变更记录；`启动与构建指南` 计数；`AGENTS.md` 硬约束 10 例外

**两个刻意偏离 §2 硬规则的点**（已在 motion.md/AGENTS.md 备案）：
1. 时长是数据（toast timeout 3.2–6s）不是动效档位 → 内联 `animation-duration`，同 FLIP 的 JS 侧补间先例
2. 缓动必须 `linear`：条长是剩余时间的读数，ease 会让读数失真（前慢后快 = 报少了再补）

**挂起同步的坑（本次最深的坑）**：
- base-ui 计时器是记账式暂停（pauseTimers 存 remaining，恢复接着跑）；条若只顾自己缩短 → "条走完了、toast 还在"
- 能白嫖的：每条 toast 根上的 `data-expanded`（= hovering||focused）覆盖悬停/聚焦/触屏/退场收尾
- DOM 缺失需镜像到 `<html>`：`data-toast-window-blurred`（handleWindowBlur 不留痕）、
  `data-toast-force-run`（handleWindowFocus / mouseleave / focusout 会**无条件** resumeTimers，哪怕 expanded 还挂着）
- 豁免的收回门槛必须逐一对齐 base-ui 判断：focusin 只认 `:focus-visible` 且 `if (focused) return` 早退、
  mousemove 也是重挂起入口（handleMouseEnter 双绑 mouseenter+mousemove）、新 toast 落地整体 pause
- `getStateAttributesProps` 假值**不渲染**属性（非 `data-x="false"`），存在性选择器语义正确

**验收**（一条命令内跑完）：build ✓ / nav_check ✓ / design_check ✓ / motion_check **33/33** ✓ /
design_audit 合规（无裸写时长、无 transition-all）/ doc_ref_check 136 处引用零失配。
特写截图核实：条贴底边、圆角裁切自然、与左侧状态条同色一体、scaleX 与剩余寿命吻合。

**已知残差**（可忽略）：鼠标移开恰逢退场动画时，base-ui 把 resume 推迟到收尾结束，条早走 ≤160ms。
