# 鼠标主题工具应用图标：主题叠片

日期：2026-10-22。状态：可评审的原创矢量设计稿，附 PNG 与 Windows ICO 导出。

## 项目分析

本方案阅读了项目决策记录、需求描述、设计规范、`src/App.css`、侧栏与页面定义、前端主题服务、Rust 命令注册和 Tauri 打包配置，并参考了现有图库截图。

- **定位**：面向 Windows 10/11 的轻量、本地光标主题管理工具。
- **核心任务**：聚合系统方案和导入的 ZIP 主题，预览静态 CUR 与动态 ANI，一键应用或恢复默认，管理与导出主题，回溯最近使用。
- **核心对象**：一整套包含多个槽位的光标主题。图标用叠片表达方案集合，用单个指针代表光标这一品类。
- **产品性格**：直接、可靠、轻量、秩序清晰。当前界面以中性黑白灰、适度圆角和轻阴影为主。
- **品牌命名现状**：界面显示“鼠标主题工具”；Tauri productName 为 `mousetool-theme`；数据目录使用 `CursorStudio`。图标采用纯图形，便于以后统一名称。

## 设计理念

方案名称为“主题叠片”。前方白色箭头建立对鼠标光标的即时识别；后方两张错位的青蓝卡片表达主题收藏、浏览与切换。深色底板与界面的中性色体系呼应，有限的彩色面积为桌面快捷方式提供辨识点。

以扁平几何造型为主，用轻微投影交代前后关系。界面里的主题内容可以很多样，品牌图标保持稳定、克制。动态图标预览、最近记录等能力通过产品界面表达，不在这个小图形里继续添加符号。

## 构图

- SVG 基准画布为 1024 × 1024。石墨色底板四角半径 208，圆角外区域透明。
- 白色箭头朝左上，具有明确凹口与向右下伸出的尾柄；尖角和圆角卡片形成形状对比。
- 后方蓝卡向右上错位，前方青卡向左下错位，叠放顺序为：底板 → 蓝卡 → 青卡 → 指针。
- 前景约占画布宽度 60%、高度 58%，保留约 17%–24% 的边缘空间；重心略高，供桌面图标使用。
- 不加文字。应用名称由系统快捷方式标签、窗口标题或界面文字提供。
- 当前小尺寸 PNG 来自主图的高质量缩小；16–24 px 若进入最终发布阶段，可继续按目标显示倍率手工调整像素与层间距。

| 石墨黑 | `#202329` | 稳定的底板，呼应现有中性界面 |
| 冷白 | `#F6F8FC` | 主指针，与底板形成强对比 |

## 交付素材与使用建议

**目录分工**：设计源留在 `assets/icon/`，打包成品在 `src-tauri/icons/`，前端 favicon 在 `public/`。`src-tauri/icons/` 只保留 Tauri 真正消费的文件。

| 素材 | 交付文件 | 建议场景 |
|---|---|---|
| 可编辑矢量源 | `assets/icon/icon.svg`，1024 viewBox | 后续改色、调整比例、重新导出；文件含 SVG 投影滤镜 |
| 高清栅格母版 | `assets/icon/icon-master-2048.png`，2048 × 2048 RGBA | 宣传页、文档封面及大尺寸展示 |
| 通用主图 | `assets/icon/icon-1024.png`，1024 × 1024 RGBA | README、关于页、素材归档 |
| 评审图 | `assets/icon/preview.png`，1400 × 850 | 浅深背景、小尺寸效果与配色展示 |
| 生产提示词 | `assets/icon/prompt.txt` | 复现或再交给图像模型 |
| 构建脚本 | `assets/icon/build_assets.py` | `python assets/icon/build_assets.py`（需 Pillow） |

`build_assets.py` 是**唯一**的产出入口，一键重建全部成品：

| 产出位置 | 文件 |
|---|---|
| `src-tauri/icons/` | `32x32.png`、`128x128.png`、`128x128@2x.png`、`icon.png`(512)、`icon.ico`(16/20/24/32/40/48/64/128/256)、`icon.icns`(ic07/08/09/10)、10 个 `Square*.png` 与 `StoreLogo.png` |
| `public/` | `favicon.svg`、`favicon-32.png`、`favicon-128.png` |

PNG 使用 RGBA，底板内部为不透明色，圆角外为透明区域；无需背景抠除。不以 JPEG 作为图标交付格式。

ICNS 由脚本手搓字节写出（Pillow 不支持这个容器格式）：`icns` 魔数 + 总长 + 若干 `[类型4B + 块长(含头8B) + PNG 数据]`，PNG 直接内嵌是合法的。

## 已接入的位置

- **系统层**：`src-tauri/icons/` 已被替换为这套图标，`tauri.conf.json` 的 `bundle.icon` 无需改动（沿用 Tauri 标准文件名）。Windows 任务栏、开始菜单、文件资源管理器、快捷方式都用它。
- **favicon**：`index.html` 引用 `public/favicon.svg` + 两个 PNG 兜底；模板残留的 `vite.svg` / `tauri.svg` 已删除。
- **侧栏品牌位**：`src/components/brand/BrandMark.tsx` —— 只取指针轮廓的**单色**版本，用 `currentColor` 跟随主题。

侧栏为什么不用完整图标：那个图标有四个形状（底板 + 两张卡片 + 指针），缩到 20 px 时指针和青蓝卡片糊成一团蓝色斑块，认不出是什么。加石墨底板更糟——深色模式下底板会和背景融掉，只剩一个悬空箭头。单色指针在 20 px 下明暗两套都锐利，且形状与系统图标同源。`design_check.mjs` 有一条断言守着这个位置（`侧栏品牌位用品牌指针`）。


## imagegen2 请求记录

已按用户指定的 imagegen2 技能，使用 UV 调用生成脚本。

- 请求模型：`gpt-image-2`。
- 比例 / 分辨率 / 映射尺寸：`1:1` / `2K` / `2048 × 2048`。
- 质量 / 输出格式 / 背景参数：`high` / `png` / `auto`。
- 未发生模型自动切换。
- API 返回：HTTP 401，`API_KEY_DISABLED`。没有取得模型生成图片。
- 精确生产提示词保存在同目录 `prompt.txt`。提示词要点为：石墨色背景、白色左上指针、青蓝色叠放主题卡片、克制几何造型、清晰小尺寸轮廓、无文字。
- 本次实际交付为依据以上方向绘制的原创 SVG 与程序化栅格导出，并非 imagegen2 成功生成的图片。

## 视觉检查记录

已查看主图和包含浅深背景、64 / 48 / 32 / 24 / 20 / 16 px 实际尺寸的评审图。扩大了前景图形，以减少留白对小尺寸识别的影响。小尺寸以白色指针为主要识别点，青蓝叠片为辅助；这不等同于 Windows 安装包和系统壳层内的实际验收。

接入后又做了一轮 20 px 实证：把 1024 主图缩到 20 px 再用最近邻放大 12 倍观察，**指针与青蓝卡片确实糊成一片**，证实了「侧栏改用单色指针」的决定不是审美偏好，而是可读性约束。
