# 功能迭代规划：自动备份（决策 32）+ 定时切换主题（决策 33）

## 选型说明

**筛选依据**：① 代码库现状——决策 10 已拍板不做项不重提、收藏此前已搁置、主题完整性体检已由 feature/theme-integrity 分支覆盖；② 联网检索同类工具趋势——Custom Cursor for Windows（https://custom-cursor.com/en/products/custom-cursor-for-windows）、Stardock CursorFX 等的高频能力集中在定时/自动切换与快捷操作，社区普遍诉求是「自动化」与「数据安全」。

| 模块 | 核心价值 | 优先级依据 |
|---|---|---|
| ① 自动备份 | 数据安全：回收站只兜「误删除」，磁盘故障/误清空兜不住；每天一份自动备份进备份历史、保留最近 N 份可恢复 | P1：复用整条既有备份链路、零新依赖、风险最低、价值最硬 |
| ② 定时切换主题 | 把决策 25 的自动化（跟随系统深浅色）扩展到「按时间段」（如上班低调/下班炫彩），同类工具高频功能 | P2：纯前端逻辑 + 设置字段，零新依赖；需与既有自动切换做优先级仲裁，复杂度中等 |

**边界关系**：两模块均为「叠加设置项」，不改任何既有命令语义；默认设置（开关全关）下行为与现状完全一致。与光标守护（决策 29）、跟随系统切换（决策 25）的退让规则在决策记录里显式定义：定时窗口内且期间主题已设 → 定时优先、深浅色切换让位；手动还原默认后两者都挂起；光标守护语义不变。不做：收藏（搁置）、市场页（未来范围）、完整性修复（theme-integrity 分支）、自制方案/单光标替换（决策 10）、全局热键（按你的选择另行决策）。

## 模块一：自动备份（决策 32）

**后端 `src-tauri/`**：
- `utils/settings.rs`：`AppSettings` 加 `auto_backup_enabled: bool`（默认 false）、`auto_backup_keep: u32`（默认 10），`Default` 同步（旧 settings.json 缺字段自动走默认）。
- `commands/backup.rs`：新命令 `run_auto_backup`（第 32 个命令）：取 `ops::try_begin("自动备份")`；扫 `backups\` 一级目录，存在 `cursorstudio-backup-auto-` 前缀且时间戳为今天的文件 → 返回 `{created:false, skipped:true}`；否则复用 `export_to_with_progress` 落盘 `cursorstudio-backup-auto-YYYYMMDD-HHmmss.zip`（进度回调 no-op，不发 `backup-progress`，避免污染手动备份进度 UI）；成功后按 keep 清理最旧 auto 备份，手动备份不动；`list_backups` 的 `BackupEntry.kind` 推导：auto 前缀 → `"auto"`，否则 `"manual"`（现有条目不变）。
- `commands/settings.rs`：`SettingsSnapshot` 补字段；`update_settings` 增 `auto_backup_enabled: Option<bool>`、`auto_backup_keep: Option<u32>`（keep 校验 1–100，非法中文报错）。`lib.rs` 注册新命令。

**前端 `src/`**：
- `services/settings.ts`：Snapshot/Patch 加字段、`updateSettings` 实参表加两列（逐字段 camelCase 既有写法）、mock 实现 `runAutoBackup`（内存 mockBackups 去重/清理；`?mock-backup-old=N` 注入 N 份旧自动备份供验收）。
- 新 `lib/auto-backup.ts`（仿 `auto-switch.ts` 骨架）：订阅 settingsStore；设置与主题列表就绪后检查一次；窗口 focus 节流（≥30 分钟）再查；开关从关到开立即尝试。失败静默（「没有可备份内容」/锁占用视为正常），其余失败 `toast.warning` 一次。
- `App.tsx` 挂载 `initAutoBackup()`；`DataSection.tsx` 数据备份卡片加「自动备份」Toggle + 保留份数 select（5/10/20），`data-auto-backup-*` 定位属性；`BackupHistorySection.tsx` auto 条目显示「自动」标记。

**测试**：`backup.rs` 模块内单测（`use_test_roots` 沙箱）：当日去重、超保留数按时间清理且不误删手动备份、kind 判定；`settings.rs` 往返补新字段。新 `scripts/auto_backup_check.mjs`（仿 `guard_check.mjs`）：开启 → 备份历史出现「自动」条目；当日重复不新增；注入旧备份 → 清理到保留数；关闭后不动作。

## 模块二：定时切换主题（决策 33）

**设置字段**：`schedule_switch_enabled: bool`（默认关）、`schedule_start`/`schedule_end: String`（"HH:MM"，后端严格校验 24 小时制，默认 "09:00"/"18:00"）、`schedule_in_id`/`schedule_out_id: Option<String>`（期间内/期间外主题，空串=清空，沿用 `normalize_theme_id` 语义）。

**前端**：
- 新 `lib/schedule-switch.ts`：整抄 `auto-switch.ts` 状态机（armed/applying/suspended/scheduled + `queueMicrotask` 去抖 + 双 store 订阅 + `initScheduleSwitch(): () => void`）；触发 = 初始化、设置字段变化、窗口 focus、`setTimeout` 到下一个时间边界（设置变化后重算；不轮询）；支持跨零点窗口（start > end 视为跨夜）。
- **优先级仲裁（关键改动，写入决策 33）**：`auto-switch.ts` 增加让位规则——`schedule_switch_enabled && 处于窗口内 && schedule_in_id 非空` 时深浅色切换不动作，窗口外照旧；手动还原默认同样让 schedule 挂起。`cursor-guard.ts` 不改。
- `GeneralSection.tsx` 新 SettingCard「定时切换主题」：Toggle + 两个 `<input type="time">` + 两个 `ThemeMappingSelect`（期间内/期间外主题，「不切换」=空串），`data-schedule-*` 定位属性；`services/settings.ts` 同步字段与实参表。

**测试**：`settings.rs` 往返 + "HH:MM" 校验单测（非法格式/越界拒绝）。新 `scripts/schedule_check.mjs`：全日窗口（00:00–23:59）→ 自动应用期间内主题；跨零点窗口（22:00–06:00）白天不动作；期间主题空串不切换；让位规则——定时命中态下模拟系统深浅色翻转，auto-switch 不动作；`auto_switch_check.mjs` 全量回归仍过。
