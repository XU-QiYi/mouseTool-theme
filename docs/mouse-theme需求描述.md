## 0. 范围

**产品定位**：一个 Windows 桌面小工具，把光标主题管起来——导入、预览、一键应用、随时还原。

**当前范围**

| 能力 | 一句话 |
|---|---|
| 主题聚合 | 系统注册表里已有的光标方案 + 本工具导入的主题，同一屏列出 |
| 导入 | `.zip` 主题包（文件选择器）或整个主题文件夹（拖进窗口）都能导入，自动识别 15 个槽位 |
| 预览 | 静态 `.cur` 与动态 `.ani` 都能在应用内真实播放 |
| 应用 | 一键写入注册表并立即生效，**无需管理员权限**；驻留托盘时右键菜单可直接切最近使用的主题或还原默认（决策 30） |
| 还原 | 一键回到 Windows 默认光标 |
| 管理 | 重命名、删除（可多选批量移入回收站，决策 43）、导出为 `.zip` |
| 最近使用 | 每次应用记一条使用事件；界面按主题去重后最新在前 |
| 备份 | 手动 / 每日自动备份全部主题与历史；备份历史可只读浏览包内主题，并按套恢复其中一套（决策 32/34） |
| 设置 | 五分组管理面板（决策 14）：**通用** = 应用主题三态 / 跟随系统深浅色自动切换主题 / 定时切换主题（默认关闭，决策 33）/ 光标守护（启动或系统改写后自动恢复上次主题，默认关闭，决策 29）/ 开机自启动 / 关闭行为（直接退出·最小化到托盘）/ 主题存储目录（可搬迁，确认框展示源/目标/数量/大小，执行期锁定并显示进度，失败可重试）/ 自动检查更新；**快捷键** = 应用内快捷键一览与开关；**数据** = 数据目录、备份导出与合并恢复、自动备份（默认关闭，决策 32）、备份内容浏览与单主题恢复（决策 34）、回收站（恢复 / 彻底删除 / 清空，决策 26）、诊断信息一键复制；**系统集成** = 鼠标属性面板直达 + 主题文件右键菜单导入（**试点**，`.zip` / `.themepack` / `.theme` 三类一把注册，决策 12/41）；**关于** = 版本 / 开源地址 / 检查更新（GitHub Releases）。设置修改即时生效并持久化 |

**明确不在当前范围**

| 项 | 为什么不做 | 备注 |
|---|---|---|
| 自制方案（逐槽位上图拼一套） | 要新增图片转 `.cur`、热点编辑、方案编辑器三块，成本远高于"导入现成主题"这条主线 | **2026-10-22 拍板不做**（决策 10） |
| 替换单个光标 | 与自制方案同源；槽位卡当前**不可点**，也不做 hover 暗示 | **2026-10-22 拍板不做**（决策 10） |
| 在线主题商店 | 涉及托管、审核、版权，超出工具定位 | 不做 |
| 多语言 / 语言切换 | 后端错误文案、右键菜单、`.inf` 注释均为中文，半吊子 i18n 比没有更伤体验 | 仅简体中文（决策 14，候选设置项中明确不做的一个） |

> 原在本表的「文件夹导入」「解析 `.inf` 槽位映射」两项已于 2026-10-24 转正实现（决策 16 / 决策 15），从本表移出，现状见 §9 与第 2 节。

## 1. 主题来源

| 来源 | 判定 | ID | 能否删除 |
|---|---|---|---|
| 系统方案 | `HKCU\Control Panel\Cursors\Schemes` 下的每个值 | `sys_<方案名>` | 否 |
| 用户主题 | `%LOCALAPPDATA%\CursorStudio\themes\<uuid>\`（可在「设置 → 通用」换成别的目录） | UUID | 是（非使用中时） |

- 三个页面**各是一个独立视图**，不只是同一张列表换个过滤条件：
  - 「主题图库」= 全部方案的分组网格，任务是**逛和挑**；
  - 「我的主题」= 导入方案的表格，能看到槽位覆盖、导入时间，任务是**管**；
  - 「最近使用」= 按自然日分组的时间轴，任务是**回溯**，且不挂右侧检查器。
- 系统方案在**检查器**里标「系统方案」徽章；正在使用的主题在卡片/行内标「使用中」，侧栏底部另有常驻的「当前光标」状态卡。
- **「正在使用」不是界面自己记的**，由后端拿注册表当前光标路径与各主题槽位路径比对得出。识别不出时（系统默认光标、用户手工改过设置）显示为空，不瞎猜。

## 2. 导入

**入口**：侧栏「导入主题」按钮 / Ctrl+O → 系统文件选择器（`.zip` / `.theme` / `.themepack`）；**拖放** → 全窗拖入 `.zip`、`.themepack` 主题包、`.theme` 光标方案（决策 36/39）或整个主题文件夹（决策 16）；**右键菜单**（试点，决策 12/41）→ 三类主题文件上点「用鼠标主题工具导入」，经 `--import` 转交。

**流程**

1. 来源分流（决策 16/36）：文件夹直接递归扫描；压缩包先校验再**流式**解压到临时目录（每次 64KB，不整个读进内存）；`.theme` 方案不走解压，按 1MB 文本上限读取（BOM 识别编码）后解析 `[Control Panel\Cursors]` 段。压缩包 / 文件夹通路共用 `THEME_LIMITS`（决策 18）：解压总量 **50MB**、单文件 **20MB**、最多 **512 个条目**、目录最多 **8 层**；文件夹按光标文件 + `.inf` 的总条目数、总体积与递归深度计。条目名必须通过白名单（拒绝 `..`、盘符、控制 / 非法字符、Windows 保留名）；任何超限立即失败、说明原因，并清理临时目录与半成品主题目录。目录里的符号链接 / 目录联接一律跳过并随导入结果返回 warning。
2. 扫描 `.cur` / `.ani`（含 `.ico`），包里带 `.inf` 时先按说明书映射槽位（决策 15），剩余槽位按文件名推断（先精确短名，再关键字包含）；`.inf` 也走 1MB 上限的字节读取，由解析器按 BOM 识别 UTF-16LE/BE 或 UTF-8，读不出的说明书跳过并 warning。
3. 落盘到 `themes/<uuid>/`，写 `theme.json`；**槽位路径只存相对主题目录的路径**（如 `cursors/arrow.cur`），运行时再拼绝对路径——主题目录以后搬到哪都自洽（决策 17）。
4. 列表刷新；新主题在「主题图库」和「我的主题」里都被选中，右侧检查器直接显示它（不强制跳页，也不清掉用户当前的搜索词以外的上下文）。

**失败要能说清原因**（现有文案范式）：

| 情况 | 提示方向 |
|---|---|
| 包里没有光标文件 | 提示"不要把说明文档单独打包" |
| 一个槽位都认不出 | 提示按什么命名，别只说"格式不支持" |
| 包太大 | 给出实际大小与上限（总量 / 单文件） |
| 文件太多或层级过深 | 说明条目数 / 层数上限，提示精简目录后重试 |
| 条目名不合法 | 指出是路径穿越、非法字符还是保留名，整包拒绝 |
| 方案引用全部落空 | 提示「没有可用的光标条目」：值都是空（系统默认）或引用的文件找不到 |
| 解压/写盘失败 | 中文主句 + 括号内技术细节 |

**约束**

- 不覆盖同名主题：每次导入都是新 UUID，名称重复不影响。
- 落盘时光标文件**按槽位重命名**（`arrow.cur` / `busy.ani`），同一槽位出现多个文件只取第一个，保证一个槽位一份文件。
- 临时目录在成功或失败后都要清理。
- 槽位来源（2026-10-24 起）：包里带 `.inf` 时按说明书映射，否则按文件名识别；说明书指向的文件不在包里时该槽位也退回文件名（见 §9、决策 15）。
- `.zip` 与整个主题文件夹都能导入（决策 16），流程同一条。
- `.themepack`（Windows 官方主题分装，CAB 容器）与 zip 同链路（决策 39，依赖 `cab` crate；LZX/Quantum 压缩不支持）；包内 `.theme` 是说明书级映射（同 `.inf` 优先级），被映射认领的文件不再参与文件名推断。
- `.theme` 光标方案收编是**复制**（决策 36）：方案段键名与注册表槽位同名、直接映射；引用的系统光标或主题包文件按槽位复制进新主题目录，源文件留在原地（语义同「保存当前光标」）；引用缺失 / 非光标格式只跳过该槽位并 warning，全部落空才拒绝；`%Var%` 环境变量大小写不敏感展开，相对路径以方案文件所在目录为基准。

## 3. 预览

| 位置 | 内容 |
|---|---|
| 主题卡 | 封面取槽位列表第一个；槽位按标准顺序排列，正常就是「正常选择」 |
| 详情区 | 4 列网格，只列该主题实际提供的槽位（缺项不占位）；单个文件缺失或损坏时显示占位图 |
| 动态光标 | 逐帧播放，帧间隔取 `.ani` 自带的 rate |

- 预览底必须是**棋盘格**：光标多为透明 PNG，纯色底会让白色光标整个消失。
- `.ani` 由 Rust 解码成帧序列交给前端 canvas 播，**不生成 GIF 文件**（决策 4）。
- 解析失败**不报错、不阻塞**：显示占位图，其余槽位照常显示。
- **文件完整性是读列表时顺带的只读体检**（决策 31）：主题声明了的槽位文件读不到时（被手动删改、外部工具动过），「我的主题」行内、检查器与诊断中心提示缺口；**只提示不拦截**——应用等命令行为不变。空槽位（主题没提供）不算缺口，那是部分覆盖。

## 4. 应用与还原

**应用**

1. 按 15 个槽位写入 `HKCU\Control Panel\Cursors`（未提供的槽位写空字符串，回落到系统默认），同时写 `SchemeName`，让系统「鼠标设置」里显示当前方案名。
2. 调 `SystemParametersInfoW(SPI_SETCURSORS)` 刷新 —— **只传 `SPIF_SENDCHANGE`**，不带 `SPIF_UPDATEINIFILE`（见决策 2 附注）。
3. 成功后向 `history.json` 追加一条使用事件；记录失败不影响光标已切换的事实，但要提示（界面「最近使用」由事件流派生）。

> 当前实现只写 `Cursors` 下的槽位值与 `SchemeName`，**不**写 `Cursors\Schemes`。若要补写，需要先想清楚：那个键是系统「鼠标属性」的已保存方案列表，写进去的方案会出现在用户的下拉框里。

- 全程普通用户权限，**不允许出现 UAC 弹窗**。
- 光标文件留在 `%LOCALAPPDATA%` 原地，不复制进 `C:\Windows\Cursors`（决策 2）。
- 目标值 < 500ms。

**还原**：清空各槽位值并同样刷新，回到 Windows 默认。

**光标守护**（决策 29，默认关闭）

- 入口在「设置 → 通用 → 外观」：开关 + 当前可恢复目标的状态行 +「立即恢复」。
- 开启后：**启动时**若当前没有可识别的本应用主题（系统默认或被外部改写），恢复上次使用的主题；应用运行期间**聚焦发现光标被外部改写**时自动夺回；「跟随系统切换主题」开启时优先恢复当前深浅色的配对主题。
- 只恢复主题库里仍存在的方案；配对主题被删除时不拿历史顶替；注册表或主题列表读取失败时不动作。
- 运行期不覆盖「系统默认」：手动「还原系统默认」在本会话内不会被立刻抢回。需要登录后恢复时配合「开机自启动」；应用未运行则不会恢复。
- 「立即恢复」不依赖开关；没有可恢复目标时禁用并说明原因。

**已知限制**（不是缺陷，任何第三方主题工具都一样）：UAC 提示框、登录界面、锁屏等**安全桌面**上仍显示系统默认光标。

## 5. 主题管理

| 操作 | 规则 |
|---|---|
| 重命名 | 仅用户主题可改；只改 `theme.json` 里的显示名，**目录名保持 UUID**；`updated_at` 不动（界面承担"导入于"语义）；名称 1–40 字，禁控制字符；值没变不发请求；正在使用的主题改名后，注册表里的 `SchemeName` 要等下次应用才同步 |
| 删除 | 系统方案不可删；使用中的不可删（按钮禁用 + store 拦截 + 后端校验 ID）；删除是**软删除**：整目录移入回收站，二次确认说清「会连同几个光标文件一起移入回收站、可恢复」；使用中的主题仍要先切换或还原 |
| 批量删除 | 仅「我的主题」：点「批量整理」进入，逐行勾选或全选（使用中的复选框禁用），一次确认把所选全部移入回收站；部分失败只影响失败的那套（其余照常删除），提示首条原因并保留失败项供重试；换搜索词清空勾选，删除范围永远等于眼前列表；勾选只在当前页面会话内，不落盘（决策 43） |
| 保存当前光标 | 仅当光标被外部改写（槽位非空但不匹配任何已知主题）时出现；复制当前非空槽位为我的主题，名称「当前光标 YYYY-MM-DD HH:MM」；全部抄全时立即应用并接管，有槽位不可用时只保存不自动应用；与已知主题一致时拒绝重复保存 |
| 导出 | 导出为 `.zip`，包内文件**按槽位命名**（`arrow.cur`、`busy.ani`），保证"导出→再导入"能还原到同一槽位；包内 `theme.json` 同样只写相对路径 |

**回收站**（决策 26）

- 位置 `%LOCALAPPDATA%\CursorStudio\trash\<条目 UUID>\`；条目里保留原主题目录与一份 `.trash.json` 快照（名称 / 删除时间 / 槽位数 / 体积）。条目 ID 与主题 ID 分开，同一主题可以删除多次。
- 最多保留 **20 套或 512 MB**，超限自动清理最早的；删除结果会说明本次自动清理了几套。
- 恢复前重新校验快照、`theme.json` 与目标目录（不能已有同 ID 主题）；损坏条目仍列出但不可恢复，只能彻底删除。恢复落到**当前**主题目录。
- 回收站不进入主题列表、备份、最近使用与目录迁移；「清空回收站」才真正删除文件。

**批量整理**（决策 43）

- 入口在「我的主题」工具条：进入后出现逐行复选框与表头全选（未选 / 半选 / 全选），工具条换成「已选 N 套 / 全选 / 删除所选 / 退出整理」。
- 只作用于用户主题；正在使用的主题复选框禁用并说明原因，系统方案不在此页。确认框点名要删除的主题，明确「进入回收站、可恢复」。
- 部分成功：单套被拒绝（例如刚好被其它操作改成使用中）只影响该套，其余照常移入回收站；提示首条失败原因，失败的勾选保留在原处供重试，不会把已成功的删除回滚。
- 换搜索词会清空勾选，删除范围永远等于眼前列表；离开页面或主题库清空即退出整理模式，勾选不落盘。

**保存当前光标**（决策 28）

- 入口在侧栏「当前使用」卡：只有状态为「被系统设置修改」时显示「保存并应用」；系统默认或已知主题不显示。
- 逐个复制当前非空槽位的光标文件到新主题目录；单文件 20MB、总量 50MB 上限与导入一致，同一源文件被多个槽位引用只复制一份。
- 当前槽位全部复制成功才自动应用并接管（状态变为「当前使用中」）；有槽位不可用（缺失 / 非光标 / 超限）时只保存、不自动应用，并在结果里列出跳过原因。
- 当前光标已经是已知主题（系统方案或我的主题）时拒绝保存，避免重复副本；捕获失败不留下半成品目录。

**存储与迁移**（决策 17）

- 槽位路径在磁盘上一律相对主题目录；旧版本留下的绝对路径仍能读，备份恢复或迁移时自动改写。
- 更换主题存储目录先预检、再确认：确认框展示源目录、目标目录、主题数量与体积；**目标必须为空**，若其中已有同名主题则点名拒绝，**不删除任何文件**。
- 执行期间锁定相关操作并显示阶段进度（复制 → 校验 → 切换 → 重绑注册表 → 保存设置 → 清理）。先写暂存目录、校验通过后原子切换；设置写入或注册表重绑失败会整体回滚，原目录与设置保持原样。
- 迁移成功后才清理原目录；清理失败只提示，不影响使用。正在使用的主题会重绑到新目录的路径，「正在使用」状态不变。
- 备份导出与恢复同样执行相对路径重写：导入备份后即使再换主题目录，预览、应用与「正在使用」仍正确；把备份恢复到新的根目录后功能可用。

**备份内容浏览与单主题恢复**（决策 34）

- 入口在「设置 → 数据 → 备份历史」：每份可读备份的行内有「查看内容」，弹窗列出备份里能恢复的主题（名称、槽位数、文件数、缺文件数、体积、导入时间）；不新增页面或导航。
- 已在主题库里的同 ID 主题标「已在主题库」并禁用恢复；零槽位主题标「没有槽位」；声明槽位全部缺文件的主题标「没有可用文件」并禁用恢复；损坏 / ID 不一致的主题不列出，集中提示。
- 部分槽位缺文件的主题仍可按套恢复：恢复后主题库按决策 31 标出缺口，恢复结果的提示点名缺失槽位；全部槽位都没有文件时命令层拒绝并清理半成品。
- 恢复是**追加**语义：只解压选中的一套到当前主题目录，保留原名称、描述和导入时间；**目标 ID 已存在时拒绝**，不覆盖、不改名、不碰原目录；不合并使用记录、不影响备份里的其它主题。
- 落盘仍写相对路径；旧备份里的绝对路径按主题 id / 文件名映射到新根目录；读回后清掉未知 / 重复 / 越界槽位，非法数据不允许落盘。
- 失败清理本次新建的主题目录，不留半成品；成功后在「我的主题」与「主题图库」里选中恢复的主题。
- 整包合并恢复（`import_backup`）语义不变；外部 `.zip` 走「从文件恢复」：**先在内容弹窗里看清单（决策 42），再选单套恢复或转整包合并确认**——单主题恢复入口同样覆盖外部备份（命令层本就接受任意合法备份路径）。

## 6. 最近使用

- 存储：`%LOCALAPPDATA%\CursorStudio\history.json`，磁盘上是**使用事件流**（v2：`{version, events[]}`），每次应用追加一条，上限 200 条。同一主题反复应用会留多条事件——它记录的是「什么时候用过什么」，不按主题合并。
- 界面上的「最近使用」是**派生视图**：从事件流按 `theme_id` 取最新一条，最多 50 个，最新在前；折叠在后端完成，前端不另存一份。
- 每条只存**名称快照**，不存整份主题：主题被删后历史仍能说清"上次用的是哪个"。
- 被删的主题在时间轴上仍占一条，标「已删除」且不给「再次应用」——它是"什么时候用过什么"的事实，不该因为主题没了就消失。
- **版本兼容**：v1 的 `{version, entries[]}`（按主题去重的旧清单）仍能读，每条旧记录当作一条事件，下次写入升级为 v2；遇到不认识的更高版本只读不写并提示，防止覆盖新版本数据。
